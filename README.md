# 基于 XGBoost 的抖音微短剧热度预测与影响因素分析

> 大数据管理与运用 · 毕业设计工程
> 数据来源：抖音「AI 短剧榜」真实采集（2026-05 ~ 2026-10），共 **800 部**微短剧

本工程围绕"**一部微短剧能否成为爆款**"这一业务问题，完成从**数据采集入库 → 预处理与特征工程 → 探索性分析 → XGBoost 建模 → 影响因素归因 → 可视化预测工作台**的完整链路，全部代码可一键复现。

## 一、核心结论速览

| 维度 | 结论 |
|---|---|
| 数据规模 | 800 部剧集 · 6,769 条热评 · 11,168 条第一集评论 |
| 标签口径 | 爆款 = 榜单热度数值进入全量 **Top 20%**（阈值 **4,815 万**） |
| 最优分类模型 | **XGBoost：AUC 0.6946**（线性基线 0.6316，提升 **+0.063**） |
| 最优回归模型 | **XGBoost：R² 0.2035**（岭回归 0.0925，提升 **+0.111**） |
| 关键发现 | **评论互动**是最强单变量信号（秩相关 0.239），**评分几乎无解释力**（0.017） |
| 消融实验 | 内容属性 → 加入观众反馈，AUC 从 0.6328 提升到 **0.7189**（**+0.086**） |
| 稳健性 | 10 次随机划分 AUC **0.6860 ± 0.0528** |
| 影响因素排序 | 内容属性 60.7% ＞ 评论互动 20.4% ＞ 文本态度 10.5% ＞ 观众口碑 8.4% |
| 选题结论 | **首选** 萌宝 50% / 宫廷 47%（仅有两者置信区间下界高于基准）；**规避** 职场 / 架空 / **剧情 13.8%**（n=325，唯一显著偏低） |
| 组合跨度 | 双标签组合最优 `古代+宫廷` 46.7% 对最差 `年代+恋爱` 5.9%，相差 **40.8 个百分点** |

> **一个诚实的说明**：榜单热度数值本身高度集中（中位 4,661 万，变异系数仅 **5.97%**），
> 因此模型的价值在于**排序与分层**（谁更可能成为爆款），而非精确点位预测；
> 回归任务 R² 偏小是数据特性使然，不是模型不足。

## 二、快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 一键跑通全流程（约 3~4 分钟）
python src/run_all.py

# 3. 启动预测工作台（Flask 服务）
cd webapp && python run.py
#    浏览器打开 http://localhost:5000
```

`run_all.py` 会依次执行 7 个阶段，并在末尾打印汇总：

```
✓ 模块一 · 数据采集（真实数据加载与原始层构建）
✓ 模块二 · 大数据预处理 + 特征工程
✓ 模块一·附 · SQL 三层建模（ODS/DWS/ADS）+ 治理巡检
✓ 模块三 · 大数据分析（EDA）
✓ 模块四 · 大数据挖掘（XGBoost 建模）
✓ 模块四·附 · 部署模型导出（树结构编译为 JSON）
✓ 附加 · 端到端验证（部署模型结构一致性）
```

### 分步执行

```bash
python src/load_real_data.py      # 读取三个真实 Excel → 标准化原始层
python src/preprocess.py          # 清洗 + 特征工程 + 标签构造
python src/build_sql.py           # SQL 三层建模 + 治理巡检 + SQLite 导出
python src/eda.py                 # 8 张 EDA 图表
python src/model.py               # 5 组建模实验（约 2 分钟）
python src/export_webmodel.py     # 导出部署模型树结构（含自检）
python src/verify_webmodel.py     # 端到端验证部署模型结构一致性

# 启动 Web 服务（Flask 分层应用）
cd webapp && python run.py        # 默认 0.0.0.0:5000

# 若要写入真实 MySQL（需先建库建表：mysql < sql/douyin_schema.sql）
python src/load_mysql.py          # 巡检 + 入库；连不上 MySQL 时自动降级 SQLite
python src/load_mysql.py --check  # 只做治理巡检，不写库
```

## 五、建模实验设计

| 实验 | 内容 | 关键结果 |
|---|---|---|
| 一 · 多模型对比 | LR / 决策树 / 随机森林 / GBDT / **XGBoost** | XGBoost AUC **0.6946** 最优（GBDT 0.6853 / RF 0.6841 / LR 0.6316） |
| 二 · 热度回归 | 岭回归 / 随机森林 / **XGBoost** | XGBoost R² **0.2035** 最优（RF 0.1690 / 岭回归 0.0925） |
| 三 · 特征组消融 | 内容 → +口碑 → +互动 → +文本 | AUC **0.6328 → 0.7189** |
| 四 · 稳健性 | 10 次随机划分 | AUC **0.6860 ± 0.0528** |
| 五 · 可解释性 | 增益重要性 + SHAP | 见下节 |

分类阈值不使用固定 0.5，而是在**袋外预测**上搜索使 F1 最大的阈值（避免用测试集调参）。

## 六、影响因素分析结论

**第一大发现：评论互动量是最强单变量信号。**
`热评点赞合计`（秩相关 0.239）、`热评平均点赞`（0.235）、`第一集评论平均点赞` 构成核心信号群。
按第一集评论平均点赞分 8 档，最低档爆款率 16%、最高档 31%。

**第二大发现：口碑（评分）几乎无区分力。**
热评均分与热度的秩相关仅 **0.017**，评分档位之间爆款率无单调关系。
这提示"叫好"与"叫座"在微短剧赛道上是两件事。

**第三大发现：题材本身携带显著先验。**
`题材·重生` 增益占比 4.25% 居首，`萌宝`（爆款率 50%）、`宫廷`（47%）明显高于全站 20%。
但题材属于**内容属性**，代表的是"选题红利"而非运营杠杆。

> 注意区分两个口径：`重生` 的**增益重要性**最高，但单独看爆款率只有 20.4%（≈基准）——
> 它是**放大器而非发动机**：单独出现时中性，只有搭配时才发力
> （`重生+脑洞` 36.4%、`都市+重生` 35.5%）。
>
> 选题层面的完整结论（含置信区间与双标签组合榜）已做进工作台的
> **题材选题决策面板**，见第七节。

**SHAP 方向**：热评点赞合计 ↑、正面情感 ↑、总集数 ↑ 推高热度；
第一集评论平均字数 ↑、催更评论占比 ↑ 反而压低热度（长评多、催更多往往出现在节奏拖沓的剧上）。

## 七、预测工作台（Flask 服务）

`webapp/` 是一个**分层解耦的 Flask 应用**，启动后访问 `http://localhost:5000`。
依赖方向单向向内，与训练流水线完全隔离：

```
视图层 (templates / static)
   ↓ HTTP
接口层 (app/api · views)          路由、参数、状态码
   ↓
服务层 (app/services)             业务编排：feature / model / insight / dataset
   ↓            ↓
领域层 (app/domain)          仓储层 (app/repositories)
纯算法，零框架依赖            唯一接触文件系统
```

四个页面：

| 页面 | 路径 | 内容 |
|---|---|---|
| 工作台总览 | `/` | 核心 KPI、模型判别能力（ROC）、全局影响因素、全局特征重要性 |
| **新剧实时预测** | `/predict` | 填剧名 + 简介 + 题材 → 实时给出爆款概率、分档结论与推动因子 |
| 模型评估与归因 | `/model` | 模型对比、回归对比、消融实验、稳健性、SHAP Top 特征 |
| 数据集浏览 | `/dataset` | 题材画像、样本检索、数据质量报告 |

**新剧实时预测**是本系统的核心能力：

- **服务端实时推理**：`webapp/app/domain/forest.py` 直接遍历
  `outputs/dashboard/webmodel.json` 里的 base64 编码树结构，不加载任何 `.pkl`，
  零 sklearn / xgboost 依赖。与训练端参考实现逐样本比对，最大偏差 `1e-16`；
- **双模型对比**：`冷启动版（仅内容属性，AUC 0.668）` vs `全特征版（内容 + 观众反馈，AUC 0.684）`
  并列展示，直观呈现"追加观众反馈"带来的概率变化；
- **爽点自动抽取**：剧名与简介按词典自动识别爽点标签（重生穿越 / 复仇逆袭 / 金手指 …），
  关键词表由 `app/domain/training_config.py` 从训练侧配置同源加载，不另维护一份；
- **局部归因**：基于 SHAP 分箱查找表给出当前样本的关键推动因子及正负方向；
- **批量比稿**：一次提交多部剧集，按爆款概率排序，用于选题排期；
- **题材选题决策面板**：把"选什么题材"直接产品化——全 20 个题材的爆款率排名
  （含 **95% Wilson 置信区间**与样本量）+ 四档决策建议（首选 / 优先 / 中性 / 规避）。

> 选题决策面板的分档判据写在页面上，可直接复核：
> **首选** = 置信区间下界仍高于全站基准（统计上站得住）；
> **优先** = 点估计 ≥ 基准×1.2；**中性** = 基准×0.8 ~ ×1.2；**规避** = < 基准×0.8。
> 当前结果：首选 `萌宝 50% / 宫廷 47%`，优先 `总裁 / 古代 / 异能 / 脑洞`，
> 规避 `职场 / 架空 / 剧情`（剧情 n=325 是唯一统计上显著偏低的题材）。

> **口径自检**：服务启动时会复现训练侧的 hold-out 划分
> （`train_test_split(stratify=y, random_state=42, test_size=0.2)`）并重算 AUC，
> 与 `webmodel.json` 中记录的 0.6677 / 0.6843 逐项比对（`match = true`）。
> 不依赖划分的 AUC 是含训练集的全样本拟合度，不能用于回测展示。

> **视觉风格**：浅色工具风——单一品牌色 + 中性灰阶，无霓虹光晕与玻璃拟态。
> 答辩投影下对比度更稳，也更接近常规业务系统的观感。

## 九、复现与口径说明

- 全流程固定随机种子 `RANDOM_SEED = 42`，结果可精确复现；
- 原始 Excel 已复制到 `data/source/`，缺失时自动回退读取 `D:/小林子/`；
- 热度数值**不做截尾**（它是被预测对象，截尾会压平头部爆款差距），仅打异常标记；
- 集数做 3.5σ 截尾（上限 500 集），因个别"合集"上传达 1000 集；
- 占比类指标的分母均已显式标注（全量 800 / 有热评明细 793）；
- SQL 层两条通道列定义完全一致（`rank` → `rank_no`、剔除标识字段 `user_id`），
  MySQL 与 SQLite 产物均可直接查询 `v_heat_rank` / `v_genre_heat` / `v_comment_signal` 三个视图；
  `v_genre_heat` 的题材阈值取 `drama_cnt ≥ 19`，与建模题材特征口径（20 种题材）对齐；
- SQLite 无 `SUBSTRING_INDEX`，多标签炸开改由 Python 侧物化 `genre_split` 辅助表实现，结果集等价。
